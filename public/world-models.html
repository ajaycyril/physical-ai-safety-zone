02 / STATE MODEL

Reality has to be typed, temporal and uncertain.

ENTITY GRAPH

What exists

A canonical model for people, places, assets, robots, sensors, tasks and business objects.

  • Stable IDs + aliases
  • Parent / child topology
  • Ownership + tenancy
  • Capabilities + constraints
SPATIAL MEMORY

Where it exists

Coordinate frames and topology connect maps, rooms, zones, robot localization and geospatial estate context.

  • Global / site / room frames
  • 2D + 3D geometry
  • Occupancy + traversability
  • Zones + geofences
TEMPORAL MEMORY

How it changed

Append-only observations and events preserve sequence, causality, trends and replayable evidence.

  • Event history
  • State snapshots
  • Mission replay
  • Change provenance
PROVENANCE

Why we trust it

Every fact carries source, timestamp, confidence, derivation and freshness so inference never masquerades as observation.

  • Observed vs inferred
  • Confidence scores
  • Freshness windows
  • Source lineage
SEMANTICS

What it means

The graph attaches domain meaning: inspection required, person authorized, valve controllable, route blocked, asset critical.

  • Ontology
  • Relationships
  • Business semantics
  • Policy attributes
CAPABILITY MODEL

What can act

Robots and systems expose typed skills, payloads, precision, safety envelopes and preconditions.

  • Skill descriptors
  • Robot affordances
  • Preconditions
  • Expected evidence
03 / OPERATIONAL TRUTH × LEARNED IMAGINATION

Prediction should extend reality, not contaminate it.

The platform owns trusted state

  • OBSERVEDSensor / robot / system facts with provenance.
  • INFERREDDerived state with confidence and expiry.
  • AUTHORIZEDPolicy-approved actions and human approvals.
  • VERIFIEDOutcome evidence written back after execution.

Models supply possible futures

  • PREDICTEDTime-series, failure, occupancy and risk forecasts.
  • SIMULATEDPhysics / digital-twin rollouts and counterfactuals.
  • GENERATEDLearned scene evolution or synthetic episodes.
  • PLANNEDCandidate trajectories, actions and task sequences.
04 / PRODUCT DECISIONS

What should be native, what should be pluggable.

Native: semantic operational graph

This is the durable system of record for physical state, identity, policy context and outcome evidence.

CORE IP / DIFFERENTIATION

Native: spatial + temporal memory

History, topology, confidence and replay are what make the estate useful to humans, agents and robots.

CORE PLATFORM

Pluggable: frontier world models

Cosmos-like, video, latent, multimodal and predictive models should compete behind stable interfaces.

MODEL GATEWAY

Pluggable: physics simulation

Use the best available simulator for the embodiment and environment rather than building a generic simulator.

SIMULATION ADAPTER

Native: state contract

Every consumer receives the same distinction between observed, inferred, predicted, simulated and authorized state.

TRUST CONTRACT

Native: outcome loop

Actions and evidence return to the graph so each mission strengthens operations, evaluation and learning data.
